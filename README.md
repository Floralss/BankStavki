# BLACK — форум проекта

Готовый одностраничный форум на Firebase: авторизация (email/пароль + Google), разделы/темы/сообщения, система рангов с бейджами (как «Лидер» на скрине) и админ-панель для управления рангами, участниками и разделами.

Владелец (полный доступ ко всему автоматически, без ручной настройки): **strepoomich27@gmail.com**

## Файлы
- `index.html` — весь форум (открывается как обычный сайт, ничего собирать не нужно)
- `firestore.rules` — правила безопасности базы данных

## Шаги запуска (один раз, 10 минут)

### 1. Включите способы входа
Firebase Console → ваш проект **black-social-af844** → **Authentication** → **Sign-in method**:
- включите **Email/Password**
- включите **Google**

### 2. Разрешите домен, где будет жить сайт
Там же, в **Authentication → Settings → Authorized domains**, добавьте домен, на котором будет открываться `index.html` (например, `ваш-сайт.web.app`, `ваш-сайт.github.io`, ваш собственный домен и т.д.). Без этого шага кнопка «Продолжить с Google» будет выдавать ошибку `unauthorized-domain`.

### 3. Включите Firestore
**Firestore Database** → **Create database** (если ещё не создана) → любой регион → режим **Production**.

### 4. Вставьте правила безопасности
**Firestore Database → Rules** → замените содержимое на файл `firestore.rules` из этого набора → **Publish**.

Эти правила:
- дают вашему email (`strepoomich27@gmail.com`) полный доступ ко всему форуму всегда, без назначения рангов вручную;
- позволяют создавать ранги/разделы только тем, у кого есть соответствующее право;
- не дают участникам самим менять себе ранг.

### 5. Разместите `index.html`
Это статический файл — подойдёт любой хостинг: **Firebase Hosting**, GitHub Pages, Netlify, Vercel и т.д. Достаточно загрузить один файл.

Быстрый вариант через Firebase Hosting (если есть Node.js):
```
npm install -g firebase-tools
firebase login
firebase init hosting   # public directory: папка с index.html
firebase deploy
```

## Как это работает

- **Первый вход владельца.** Когда вы (strepoomich27@gmail.com) впервые войдёте — через Google или email/пароль — сайт автоматически создаст ранг «Владелец» со всеми правами и назначит его вам. Дополнительно создаётся базовый ранг «Участник» для всех остальных.
- **Ранги и права.** В админ-панели (иконка ⚙ вверху, видна только тем, у кого есть права) на вкладке «Ранги» можно создавать новые ранги (например «Лидер», «Модератор», «Куратор») — задать название и включить нужные права: управление рангами, участниками, разделами, закрепление/закрытие тем, удаление чужих сообщений, блокировки.
- **Оформление ранга — через CSS, не через один цвет.** Для ника и для бейджа задаются отдельные наборы CSS-свойств (`color`, `font-weight`, `text-shadow`, `background` с градиентом и т.д.) — прямо в форме создания ранга есть живое превью. Стили всех рангов одновременно применяются на сайте (не перезаписывают друг друга), поэтому у разных участников одновременно корректно отображаются разные ники/бейджи.
- **Назначение рангов.** Вкладка «Участники» — таблица всех зарегистрированных, у каждого можно выбрать ранг из выпадающего списка.
- **Разделы и темы.** Вкладка «Разделы» (или кнопка «+ Раздел» на главной) — создание категорий форума. Внутри каждого раздела участники создают темы и отвечают в них.
- **Бейджи** отображаются рядом с ником везде: в шапке сайта, у авторов тем и сообщений — цвет и название берутся из назначенного ранга, как жёлтый бейдж «ЛИДЕР» на присланном скрине.

## Если что-то не работает
- **Google-вход не открывается / ошибка о домене** → проверьте шаг 2 (Authorized domains).
- **«Missing or insufficient permissions»** → проверьте, что правила из `firestore.rules` опубликованы (шаг 4), и что вы вошли под нужным email.
- **Ранги не появляются после первого входа** → убедитесь, что входили именно под `strepoomich27@gmail.com` — только этот email автоматически получает право на создание первых рангов.
- Теперь все действия (создание ранга, раздела, темы, ответа и т.д.) при ошибке показывают всплывающее уведомление с текстом ошибки Firestore внизу экрана — раньше сбои происходили молча, из-за чего казалось, что «ничего не создаётся». Если увидите такое уведомление — в нём и будет причина (чаще всего это правила безопасности, см. шаг 4).

## Что можно доработать дальше
Это рабочая база «под ключ»: авторизация, роли, форум, админка. При желании легко добавить: загрузку аватаров (Firebase Storage), личные сообщения, поиск по темам, уведомления, лимиты на количество ранга «Владелец» и т.д. — скажите, что нужно, и это можно добавить.
